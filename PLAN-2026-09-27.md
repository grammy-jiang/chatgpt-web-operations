## 2. Why the tests did not catch it

1. **Two clients again.** This skill's `chatgpt_session.py` and
   `chatgpt_cookies.py` were copied from binnacle's
   `.claude/skills/chatgpt-mcp-dev/scripts/` on 2026-09-19 (`VENDORED.md`).
   The 2026-09-20 decision ("one client, here") retired the research-pipeline
   copy, but not the binnacle origin. Fixes landed in one copy only.
2. **Fakes at the external boundary.** The session tests injected fake
   decryptors, and the send tests use fake pages. Both encode yesterday's
   Chrome and yesterday's ChatGPT, so drift passes them.
3. **A partial fix.** The tolerant decryptor has existed since 2026-09-20,
   but only on the probe and client paths. `Session` still used the strict
   decoder, and one test asserted the strict behavior.
4. **Canary cadence.** The HTTP check runs daily at 05:25. The browser check
   ran on Fridays only, and the UI changed on a Saturday. Since 2026-09-27 the
   browser check runs daily (crontab, 05:25, `--browser`). No check covered
   binnacle's copies.
5. **Intermittent submit failures are not counted.** Nobody knows how often
   "not posted" happens.

## 3. Owner rules in force (2026-09-27)

- **Coverage:** unit tests cover each core module to at least 95 % and each

## 5. Work

### A. One client

- **A1. Add `scripts/refresh_connector.py`.** It POSTs
  `/backend-api/aip/connectors/mcp/refresh_actions` with `{"link_id": ...}`
  for a connector found by name (case-insensitive: an exact match, else a
  unique substring) or by link id. It retries HTTP 424 (the tunnel is still
  registering) 5 times, 10 s apart. The binnacle tool it replaces documents
  the request. Add offline tests and one live read-tier test (a refresh
  changes nothing on the account).
- **A2. Check the other two tools.** Confirm that this skill covers what
  binnacle's `chatgpt-chats` does: track chats by id, back up and then delete
  by id, and a ledger dry run. Also confirm it covers what `chatgpt-project`
  does: read and set a Project's instructions. Map each binnacle option to a
  skill command. Add what is missing, with tests.
- **A3. Retire the copies in binnacle.** Rewrite `chatgpt-refresh`,
  `chatgpt-chats` and `chatgpt-project` as thin wrappers that keep their
  command lines and call this skill. Delete binnacle's `chatgpt_session.py`
  and `chatgpt_cookies.py`. Update binnacle's `CLAUDE.md` wherever it
  describes them. Deploy the way binnacle deploys: CI green, a quiet moment,
  then fast-forward `master` and `proof-of-concept`. The binnacle checkout
  reloads the live server on every saved `.py` file, so work in a worktree.
- **A4. Record it.** `VENDORED.md`: the binnacle origin is retired.
  `ROADMAP.md` working rule 2: no second client in any repository.

Exit criterion: in binnacle, `grep -rl "chatgpt_session" .claude scripts`

### B. Test hardening

- **B1. Real-path boundary tests.** Each external boundary gets at least one
  test that runs the real code on realistic data, with no injected fake at
  that boundary:
  - cookie jar: done in `7364386`;
  - keyring read;
  - session renewal;
  - the composer and turn selectors against recorded page snapshots (B2).
- **B2. Recorded fixtures.** The daily browser check saves what it saw: the
  selectors that matched, the send-button test id, and a trimmed DOM snapshot
  of the composer area. The HTTP check saves the shapes of the conversation,
  connector and project responses. Offline tests run the selectors and
  parsers against these fixtures. When the check sees a change, it refreshes
  the fixture and reports WARN, so the offline suite shows what broke before
  a real run does.
- **B3. Canaries.** Keep the daily browser check (since 2026-09-27). Add the
  binnacle wrappers from A3 to the check once they exist, because they are
  entry points too.
- **B4. End-to-end send test.** A scripted send, tagged with a marker, into
  the `rp-test-sandbox` Project, checked by three facts: the post, the reply
  text, and the cleanup (the chat deleted). It runs on every change to
  `BrowserSender` or `send_prompt.py`, and weekly. It uses the owner's
  ChatGPT quota, so it sends one short message per run.
- **B5. Submit robustness.** Log every "not posted" as an event with the
  screenshot path. If it happens again, harden the submit. After `fill`, read
  the text back from the ProseMirror element and check that the send button
  is enabled. If either fails, clear the composer and type with
  `page.keyboard.insert_text`. Cover this with fake-page tests.
- **B6. Flaky tests.** A test that fails without a code change is a defect.
  Fix it or quarantine it within a week, and record which one it was.

Exit criterion: `make test` and `make lint` pass; every item above has its
test or its schedule; `TESTING.md` describes the new kinds of tests.
